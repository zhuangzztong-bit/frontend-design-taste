# Anti-AI Audit v2.0（场景契合度 + 去“AI味”双重审查技能）

当用户觉得现有页面“效果不理想”、“太像 AI 生成的”或“风格不对味”时，**禁止不问业务直接往浅色编辑风或暗黑极客风硬改**。严格按以下两阶段执行审查与改造。

---

## 第一阶段：场景契合度诊断（先治“风格错配”，20 分）
先阅读项目代码 / README / 页面内容，并对照 `design-taste-master/references/00-scene-style-router.md` 回答：
1. **产品用途与用户场景是什么？**（例如：多智能体派对互动 vs 严肃财务后台 vs 个人作品集）
2. **当前页面的风格是否错配？** 常见错配：
   - 把**互动社区 / 派对 / 游戏化产品**做成了冷冰冰的企业后台或平淡的静态博客（缺乏舞台感、角色感与即时反馈）；
   - 把**严肃 B2B / 金融工具**做成了花哨渐变卡片或低信息密度营销页；
   - 把**开发者工具**做成了满屏营销废话和抽象 3D 球体；
   - **盲目套用单一审美模板**，导致视觉调性与产品核心乐趣/核心效率脱节。

> **改造原则**：先确定最契合本项目用途的**目标流派（流派 A~F 或主副分区）**，再决定保留什么原有灵魂、重构什么视觉与交互。

---

## 第二阶段：10 项“AI 味”病灶扫描（80 分）

在选定正确流派的前提下，逐项扫描页面代码或视觉表现（标记 `[FAIL]` / `[WARN]` / `[PASS]`）：

| # | 病灶名称 | 典型“AI 味”症状 | 按场景修正方向（10 大网站标杆） |
| :--- | :--- | :--- | :--- |
| 1 | **无理由紫蓝发光** | 与品牌/场景无关的深蓝底 + 紫色霓虹光晕 + 玻璃发光框 | 替换为匹配当前流派的真实色板（如派对选 `party-stage`/`arcade-pop`，SaaS 选 `nordic-mint`/`forest-blueprint`，官网选 `warm-paper`） |
| 2 | **纯黑纯白硬对比** | 直接 `#000000` 配 `#ffffff` | 改用带色相深墨色 + 微调浅底/暗表面，建立层次 |
| 3 | **单调无衬线平庸感** | 全站只有一种 `Inter` / 系统无衬线，缺乏性格 | 引入匹配场景的三字族系统（Typewolf / Fonts In Use 映射方案） |
| 4 | **无媒介隐喻的三列卡** | 整页堆满居中图标 + 标题 + 两行字的 3 列圆角卡片 | 改用匹配业务的媒介隐喻（舞台房间、活页装订、索引目录、节点画布、精密账簿） |
| 5 | **假数据与空洞文案** | `99.9%`、`10k+`、`Lorem ipsum`、空泛口号 | 替换为真实业务高精度数据 + 对比基线（或真实鲜活的角色/场景文案） |
| 6 | **抽象概念占位图** | 首屏放 3D 发光球体、抽象连线网或无关图库图 | 直接展示真实产品界面、实时互动舞台、可玩沙盒或命令行 |
| 7 | **单薄或混乱 CTA** | 只有一个空洞 `Get Started` 或并排多个同权重按钮 | 落地页改为双轨 CTA；应用内明确唯一主动作与次级动作 |
| 8 | **廉价/错配动效综合征** | 全场 `transition: all 0.3s ease`、所有卡片无脑 `hover:scale-105 + shadow-2xl + glow`、进出场对称拖沓、大跨度飞入（`>24px`）、用阻断弹窗代替原地形变、B 端后台乱加弹跳或互动派对毫无反馈、缺失 `prefers-reduced-motion` | 对照 `06-motion-choreography-system.md` 绑定 `[data-motion]` 人格：用物理弹簧 `linear()`、退场时长 = 入场 × `0.7`、View Transitions 原地 Morph（Things take time / One Year）、Luma 光标聚光或 `.m-hover-line`、前 6 项封顶 Stagger 及保留语义的减动效淡入淡出 |
| 9 | **对比度翻车** | 亮色按钮配白字、浅灰正文看不清 | 按 Realtime Colors 规范修正至 WCAG AA（>= 4.5:1） |
| 10 | **阻断式弹窗与冰冷空状态** | 进页就弹全屏遮罩，空状态只有一行灰字 | 改为角落轻量引导浮层、内联任务清单或带温度的微动画空状态 |

## 第三阶段：专项动效深度体检（7 项必查子清单，计入微交互与温度 20 分）

当用户专门要求优化动效或页面交互质感欠佳时，必须逐条核对以下 7 项动效指标（依据 `design-taste-master/references/06-motion-choreography-system.md`）：
1. **场景-动效人格匹配度**：当前页面的动效阻尼与时长是否匹配其产品流派？（如控制台必须用零过冲 `data-motion="precise"`，派对社区可用 `13%` 过冲 `data-motion="playful"`）。
2. **合成层性能卫生**：是否存在 `transition: all` 或对 `width`/`height`/`top`/`left`/`margin` 的直接过渡？
3. **进出场非对称性**：浮层、抽屉、Toast 的退场是否采用加速曲线（`--ease-exit`）且时长收敛至入场的 `60%~70%`？是否优先采用了原生 `@starting-style` + `allow-discrete`？
4. **空间连续性（Morph vs Modal）**：二次确认（如删除）、筛选切换、卡片展开、搜索呼出是否优先采用原地共享元素形变（View Transitions `view-transition-name` 或 FLIP `layoutId`），而非生硬弹窗？
5. **悬停与按压分寸感**：是否消除了全站卡片 `hover:scale-105`？是否具备 `:active` 即时按压下沉（`90ms, scale(0.97)`）+ 场景弹簧回弹？
6. **位移与交错（Stagger）克制**：入场位移是否控制在 `6px~24px` 以内？列表交错是否限制在 `40ms × 前 6 项（<=240ms）`？
7. **无障碍与设备适配**：是否在 `@media (prefers-reduced-motion: reduce)` 下保留 `120ms` 透明度反馈并移除位移/缩放？是否用 `@media (hover: none)` 防止触屏粘滞悬停？

---

## 第四阶段：输出报告与手术级改造
1. **《场景与风格定位》**：明确本项目属于哪类流派、绑定的 `[data-theme]` / `[data-type]` / `[data-motion]`，以及之前效果不理想的根因（是“风格/动效错配”还是“AI 味病灶”）。
2. **总分评估（100 分）**：场景契合度（20）+ 色彩与对比（20）+ 排版性格（20）+ 构图与真实度（20）+ 动效与交互温度（20）。
3. **TOP 3~5 改造动作**：精确指出要改的文件/组件、推荐的 `[data-theme]`、`[data-type]` 与 `[data-motion]`，以及为什么这样改最贴合用户使用场景。
4. **改后复测**：修改后重新核对场景契合度、10 项病灶及 7 项动效子清单，确保零回归。
