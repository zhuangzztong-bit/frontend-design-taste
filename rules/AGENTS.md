# Frontend Design Taste — 反“AI味”前端审美常驻铁律

当你设计、编写或重构任何前端界面（SaaS 控制台、Web 应用、营销官网、落地页、个人作品集或交互组件）时，必须始终遵守以下源自 10 个顶级设计网站真实案例的审美底线：

## 1. 严禁默认“AI 模板套路”
- **禁用无意义紫蓝发光渐变**：不要默认使用深蓝/深黑底配紫色霓虹光晕、玻璃拟态发光边框或抽象 3D 发光球体作为主视觉。除非品牌本身明确要求，否则优先选用自然纸感浅色（如 `#fef6e4`、`#f2f4f6`、`#fffffe`）或带色相的克制深色（如 `#0f0e17`、`#16161a`、`#004643`、`#232946`）。
- **禁止“纯黑 `#000000` + 纯白 `#ffffff`”生硬对比**：用带微弱色相的深墨色（如 `#001858`、`#272343`、`#0e172c`、`#181818`）替代纯黑，用微暖白或浅灰表面（`#fffffe`、`#f9f8fc`）做层次。
- **禁止空洞的装饰性大数字与假占位数据**：不要写 `99.9%`、`10,000+`、`Lorem ipsum` 或 `Feature 1/2/3`。像 Mercury / Shopify / Cake Equity 一样，使用贴合真实业务场景的高精度数据（如 `$5,216,471.18`、`69.94% Allocated`、`Compare to: 28 Apr 2025`）。

## 2. 色彩系统必须有“角色”与“区块节奏”
- **严格控色（3~6 色上限）**：遵循 Realtime Colors 法则——2 个中性色（背景 + 文字）+ 1 个 Primary 主色 + 可选 1 个 Secondary 次色 + 1 个 Accent 点缀色。
- **区块交替（Section Alternation）**：遵循 Happy Hues 范式，相邻内容区块通过背景明暗或表面色差自然区分，并明确区分 `Headline`（高对比）与 `Paragraph`（柔和次级对比）。
- **按钮文字对比度硬约束**：明黄（`#ffd803`）、薄荷青（`#00ebc7`）、暖杏（`#ffc0ad`）等高明度按钮必须配深色文字（如 `#00214d`、`#272343`），严禁白字糊在亮按钮上；正文与按钮至少满足 WCAG AA（4.5:1）。

## 3. 排版必须建立“性格反差”
- **打破单一无衬线平庸感**：优先使用 Typewolf 与 Fonts In Use 验证过的**三级字族体系**：
  1. 展示/标题体（情绪衬线或鲜明性格无衬线，大字重配收紧字距 `-0.02em ~ -0.04em`）
  2. 正文/UI 体（高屏显可读性的中低对比无衬线，保证行高 `1.5 ~ 1.7`）
  3. 等宽元数据体（Monospace，用于日期、版本号、价格精度、索引编号 `[ 01 ]`、快捷键 `⌘K` 与状态标签）
- 财务/仪表盘数字必须开启 `font-variant-numeric: tabular-nums`。

## 4. 构图与产品展示必须“去概念化”
- **SaaS 与工具产品**：首屏直接展示真实可感知的 UI 片段、交互工作台或真实命令行/操作流（参考 Mobbin、Operate、exe.dev），拒绝抽象几何配图。
- **双轨 CTA 分层**：落地页首屏主 CTA 应提供低门槛主入口 + 探索/直达次入口（如 `Join for free` + `See plans →`，或 `Try free` + `ssh exe.dev`）。
- **物理与媒介隐喻**：优先从业务领域提取视觉隐喻（如出版物的书脊与纸张、工程工具的活页装订/等距线框、协作工具的节点画布），替代千篇一律的三列圆角卡片。

## 5. 微交互追求“连续性”与“分寸感”
- **原地过渡优于生硬跳转**：组件展开、筛选切换、搜索呼出优先采用共享空间位置过渡（参考 One Year 的 Morph 搜索栏、Dia 的长按历史预览）。
- **非阻断轻量引导**：产品引导与版本更新优先放在角落浮层、顶栏进度胶囊或内联清单中（参考 Mercury、Cake Equity、SavvyCal），避免粗暴打断主工作流的全屏弹窗。
- **高价值任务触发深度技能**：构建新页面或系统设计时，主动查阅 `design-taste-master` 技能下的 5 大维度真实案例与 CSS/Tailwind Token 预设；改造现有页面时，执行 `anti-ai-audit` 技能逐项排查。
