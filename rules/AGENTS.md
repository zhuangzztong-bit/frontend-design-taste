# Frontend Design Taste — 反“AI味”前端审美常驻铁律（v2.0）

当你设计、编写或重构任何前端界面时，必须始终遵守以下源自 10 个顶级设计网站真实案例的审美底线：

## 0. 最高优先级：先分析项目用途与用户场景，严禁“一刀切”套风格！
- **动手前必须先定性**：在写任何 UI 代码或提改造方案前，必须先基于项目代码、README 或用户描述回答四个问题：① 产品用途是什么？② 用户打开它时的心态和核心场景是什么？③ 页面真正的视觉主角是谁？④ 应传递什么情绪？
- **按场景选流派（查阅 `00-scene-style-router.md`）**：
  - 社交 / 多智能体派对 / 游戏化社区 → 活力舞台/房间隐喻、角色辨识度、高频爽感微交互（绝不做成冷冰冰的财务后台或沉闷杂志风）
  - B2B SaaS / 金融 / 数据控制台 → 克制高密度、1px 细线、`tabular-nums`、时间对比基线、非阻断引导
  - AI 画布 / 节点编排工具 → 无边界画布、悬浮 Dock、空间节点连接（打破左对话右输出套壳）
  - 开发者工具 / 基础设施 → 工程/终端隐喻、双轨 CTA（含 CLI 直达）、真实代码/沙盒
  - 品牌官网 / 作品集 / 文化出版 → 强媒介隐喻、极端留白或无 Hero 索引目录、海报级字体张力
  - 消费级效率 / 生活方式 → 温柔留白、空间连续 Morph 过渡、轻量插画温度
- **改造已有项目时**：保留产品原本正确的业务灵魂与情绪基调，只清除“廉价 AI 模板味”，绝不盲目把所有项目强行改成同一种浅色编辑风！

## 1. 严禁默认“AI 模板套路”
- **禁用无理由的紫蓝发光渐变**：不要默认使用深蓝/深黑底配紫色霓虹光晕、玻璃拟态发光边框或抽象 3D 发光球体作为主视觉。明暗基调与饱和度必须由**项目场景**决定，而非默认 AI 套路。
- **禁止“纯黑 `#000000` + 纯白 `#ffffff`”生硬对比**：用带微弱色相的深墨色（如 `#001858`、`#272343`、`#0e172c`、`#16161a`）替代纯黑，用微暖白或浅灰表面（`#fffffe`、`#fef6e4`、`#f2f4f6`）做层次。
- **禁止空洞占位数据**：不要写 `99.9%`、`10,000+`、`Lorem ipsum` 或 `Feature 1/2/3`。使用贴合真实业务场景的内容与高精度数据。

## 2. 色彩系统必须有“角色”与“区块节奏”
- **严格控色（3~6 核心色上限）**：遵循 Realtime Colors 法则——2 个中性色（背景 + 文字）+ Primary 主色 + 可选 Secondary 次色 + Accent 点缀色（多角色互动场景可用受控的角色语义色板区分身份）。
- **区块交替（Section Alternation）**：遵循 Happy Hues 范式，相邻内容区块通过背景明暗或表面色差自然区分，明确区分 `Headline` 与 `Paragraph` 的对比层级。
- **按钮文字对比度硬约束**：明黄（`#ffd803`）、薄荷青（`#00ebc7`）、暖杏（`#ffc0ad`）等高明度按钮必须配深色文字，严禁白字糊在亮按钮上；正文与按钮至少满足 WCAG AA（4.5:1）。

## 3. 排版必须建立“性格反差”
- **打破单一无衬线平庸感**：优先使用 Typewolf 与 Fonts In Use 验证过的**三级字族体系**（按场景选配展示/标题体 + 高屏显正文无衬线 + 等宽元数据体 `Monospace`）。
- 财务/仪表盘/计数数字必须开启 `font-variant-numeric: tabular-nums`。

## 4. 构图与产品展示必须“去概念化”
- 首屏直接展示与产品用途匹配的真实可感知界面、互动舞台、命令行或实景媒介，拒绝抽象几何配图与千篇一律的三列圆角卡片。
- 落地页首屏优先提供**双轨 CTA 分层**（低门槛主入口 + 探索/极客直达次入口）。

## 5. 微交互追求“连续性”与“分寸感”
- 组件展开、筛选切换、视角切换优先采用共享空间位置过渡（Morph），禁用所有卡片无脑 `hover:scale-105 + shadow-2xl + glow`。
- 引导与状态提示采用非阻断轻量容器（角落浮层、顶栏进度胶囊、内联清单），尊重 `prefers-reduced-motion`。
- 构建新页面或优化项目时，主动触发 `design-taste-master`；审查与改造已有项目时，触发 `anti-ai-audit`。
